## 已确认：一间客厅，共同事实与不同职责

项目、任务、Bug、报告、版本和部署回报保持同一份事实。页面依据当前真人、绑定的岗位机器人、实际工作责任和阶段组织重点，不因切换显示焦点改变权限、事实或投票数。上报记录与平台推断应能区分，不能把AI建议呈现为已发生的外部动作。

| 默认职责 | 工作重点 | 平台内的交互边界 |
| --- | --- | --- |
| 主管 | 项目方向、关键结论、人员承接和兜底责任 | 提出方向、处理正式报告、承接暂未有新任职者的机器人 |
| 项目经理 | 计划、任务安排、依赖、进度和异常处置 | 分配与协调、查看上报、发起范围调整、按权限确认办公流程 |
| 开发 | 自己机器人的任务、关联分支、AI进度与依据 | 手动或让本地AI登记分支；日常无需填百分比；有事项/成果再上报，完成由本人明确触发 |
| 测试 | 待验证任务、实际环境、问题与待复测事项 | 本地测试后通过界面或授权AI上报；正式Bug关联任务后直接同步修复状态，不另走一轮报告审批 |
| 运维 | 环境和发布回报、待处理发布事项、历史结果 | 本地完成测试/生产部署或升级，通过界面、CLI或本地AI回报 |
| 运营 | 已上报发布的版本、运营成果和改进材料 | 上报成果、提出改进、参与材料讨论与相应确认 |

测试不负责判断内部代码影响或根因分支。开发提供技术依据；平台可依据获准信息关联、分析、提醒和提出建议，不代替测试执行，也不操作代码或环境。角色在平台内可执行的上报、处置与审批动作应由系统权限约束，不能由提示词自行扩大。

多任务Bug由一个协调机器人收齐信息、推动整体进展，各任务责任人完成自己的工作；协调不等于代其他人开发、测试或验收。

“职责重点”与“项目全貌”继续共享详情入口。同岗多人按各自机器人承担的任务和参与关系区分；兼岗汇总本人全部责任，待决不因切换焦点消失。跨项目切换保留真人身份，只读取该项目的岗位与权限，不切换成另一个人。

## 已确认：独立机器人、主管兜底与人员交接

模型为“岗位模板 → 稳定岗位机器人 → 任职关系 → 真人”。同一岗位可设多个独立机器人，人员分别绑定；一人兼岗能力继续保留。岗位机器人承接工作责任、业务经验和上下文，项目成果仍是共同事实，不复制成每个机器人的私有项目。

**Q066明确机器人不能无人绑定。** 任职者离开而新人尚未确定时，由主管兜底承接。界面应显示实际承接人及兜底原因；主管承担责任不等于系统自动同意。替换主管本人时也必须保留有效承接关系，不能通过移除最后一名可承接者制造无人机器人。

| 交接内容 | 当前规则 |
| --- | --- |
| 未结任务、Bug、待发送报告、业务上下文 | 保持机器人责任关系，主管或新任职者接续并能查看原始依据 |
| 岗位经验、工作要求 | 随机器人保留，新任职者继承 |
| 个人表达偏好和个人提示词 | 留给本人；新人使用自己的配置，完整可见范围继续依Q023，不自动复制前任私人配置 |
| 需要从个人配置沉淀的业务经验 | 明确转为岗位知识后交接，不静默搬运完整个人提示词 |
| 历史发言、提交、批准和验收 | 保留当时真人与岗位，不改写成主管或新人作出 |
| 已结束审批 | 继续只读，不因换人重新开放 |
| 进行中的接收审批 | 接收机器人与真人任职映射变化时，按Q025确认新版并重收票；同两人互换岗位也属于变化。按Q036推导新版等待首票，同真人仍只计一票 |
| 本地身份、凭据和AI会话 | 接任者使用本人身份及获准接入，不作为机器人经验转移 |

项目负责人沿用成员管理职责执行任职替换。交接界面建议先显示未结工作、待发送报告和受影响审批，再显示新承接人；新人看到接任摘要及原记录。普通业务接续不逐项新增接受手续。离任只解除对应岗位权限，不抹掉该人在其他岗位的有效权限或历史决定。

这里的岗位权限是平台内部办公权限。Q071之后不存在通过换人把平台Git、部署等外部执行授权转给新人的产品流程。

## AI解读、正式报告与真人决定

同一报告可以按当前责任生成个人AI解读，帮助成员理解材料。正式正文、变更清单及接收集合仍是共同报告；AI解读不能改写它们，不能替人确认发送或投票。报告、个人配置或任职关系变化后，旧解读需要明确标记来源与适用范围，不能直接冒充新任职者的意见。

项目职责优先，个人提示词补充方法和表达偏好。Q067确认的岗位经验与个人偏好分层应在配置界面直接标明“随岗位交接”和“个人配置”；个人配置仍依Q023由本人和负责人完整可见，“个人”不等于负责人失去既有查看权限。

Q076已确认授权本地AI/CLI直接入本人台账，不能代人审批。Q081明确开发完成后待测试，测试通过才最终完成；Q082明确AI只更新进度分析和疑点，不凭推断撤销人工完成；正式Bug或本人退回等事件仍联动，计划跟随任务。原型通用确认按钮不代表普通进度/问题上报的产品规则。

## 原型事实与尚未验证的范围

原客厅曾实现按体验身份展示职责重点、兼岗待决、共享详情、关联跳转及只读模拟AI解读；这些是浏览器演示数据和交互，不能视为服务端认证、真实AI推理、Git核验或外部执行证据。

当前原型已提供机器人查看与替换、主管兜底、岗位知识/个人偏好展示、自由分支关联、直接上报事件、模拟AI分析、正式计划审批和资料交接。24项状态测试/8条浏览器E2E通过；自定义机器人新增配置及独立个人AI解读尚未完整接入。具体范围以[Demo说明](./Demo.md)为准，体验身份切换不代表生产登录。

Q021整体理解已获确认，Q085明确自由分支关联。本轮已同步引擎：普通Bug直接联动，开发完成与测试最终完成分开，计划/任务/Bug关联持久保存，资料目录及协调机器人可操作。AI进度依赖演示观察输入，真实Git/模型、SQLite/OpenSandbox和服务端权限尚未实现；当前测试不能替代真实集成验收。

## 工作目录与会话视图

用户提出resources和talks按机器人组织，上传内容由接任者继承；会话历史使用SQLite，AI执行采用OpenSandbox。建议长期岗位知识放项目级，计划下保留该计划的机器人材料和会话入口；正式共同议题只保存一份，不拆成每个机器人各自的结论。

Q084已确认业务会话随岗位交接，正式议题、报告和可共享依据对团队开放；前任个人提示词、私人配置不因交接自动暴露。其他原始工作会话依既有职责和内容权限提供，不能因目录名自动向全项目公开。此前仅当前任职者/负责人可见属于建议，不记成用户逐字确认的排他清单。SQLite与目录视图分工、沙箱只读输入及独立输出见[AI工作空间](./AI工作空间.md)，目录优化仍是工程建议。
