# 项目客厅的办公协作界面

当前保留项目客厅。Q071将工作边界明确为“各成员本地工作并上报，平台AI分析、提醒和建议，真人在平台完成办公确认”。界面随这条主线调整。

Q021已确认整体业务依据，Q085明确用户侧分支自由。本轮已把Demo调整为三类独立分支关联、AI进度与人工状态分离、Bug/测试直接联动；正式计划保留审批，普通工作说明不再要求填写百分比或额外发审批票。

## 首屏与项目内页

首页显示本人可参与的项目、岗位机器人和待处理事项。进入项目后显示职责重点与共享记录；配置不作为常驻左侧模块导航。

目标主线分为：关联分支/目录材料 → AI进度与依据；明确业务事件 → 任务联动 → 计划聚合；正式议题 → 人员确认 → 获准内部变更。每个状态应能打开依据，开发不必频繁填百分比，普通Bug不应被套入正式报告审批。

## 内容与动作

| 内容 | 人需要看到的内容 | 主要动作 |
| --- | --- | --- |
| 我的工作 | 绑定机器人的任务、相关计划、仍待提交的结果 | 上报本地工作、查看任务 |
| 工作上报 | 来源、作者、任务、分支/产物引用、正文、时间 | 查看材料、模拟分析、更正上报 |
| AI建议与待决 | 当前依据、建议的平台变化、疑点、发送与接收责任 | 确认发送、同意、退回重议 |
| 计划与任务 | 计划与任务各自的分支关联、AI分析依据、人工状态与测试结果 | 新建草案时列分支、维护关联、责任人完成、测试结果 |
| Bug | 多任务关联、协调机器人、独立修复分支、原报告和各部分结果 | 正式提交直接联动、修复分支关联、复测反馈 |
| 项目资料 | 按计划/机器人组织的报告文件、时间与原作者 | 上传业务文本/图片、目录浏览、只读预览和来源跳转 |
| 发布回报 | 哪个计划/分支/版本在何环境已发布、谁上报、结果 | 回报本地发布、核对报告 |
| 机器人 | 职责、任职者、岗位知识、个人偏好 | 替换绑定人、由主管承接 |

“已上报”“AI判断”“已确认平台变更”分开标识。未经真实连接查询的信息不能标成外部已核验；同意报告也不显示“平台完成合并/部署”。

## 已撤下的旧交互

当前入口不再提供平台自动合feature、AI修冲突、创建release、执行传播、合main等动作。相关分支名/提交号可以作为上报引用展示，实际处理者是成员本地工具。

旧演示代码和数据保留作历史参考；当前 / 与 /demo.html 指向新的办公Demo，使用独立存储。原项目客厅链接可继续进入相应项目，不加载旧执行型状态。

## 体验边界

界面/本地AI/CLI来源用于演示统一语义，不表示真实通道已接入。分支无命名、来源或合并规矩限制；登记引用不等于实际仓库观察，演示输入与真实核验清楚区分。SQLite、OpenSandbox及服务端文件/权限还未实现，当前界面与实测范围见Demo说明。

启动及实际验证结果见[Demo](./Demo.md)，业务规则以[详细设计](./详细设计.md)为准。
