# Judex 办公协作与自由分支关联 Demo

当前入口：[项目客厅](http://127.0.0.1:4173/demo.html)。根入口 / 使用同一新版流程。用户已确认Q021业务依据，本轮按Q085补充分支只关联、不限制Git组织方式的规则。

## 启动与验证

```sh
cd docs/demo
npm run dev
npm run build
npm test
npm run test:e2e
```

当前状态测试位于src/office，浏览器用例为tests/office.spec.ts。旧执行型原型的测试仅作历史参考。开发服务只监听本机，浏览器E2E使用独立Microsoft Edge上下文。

## 体验路径

| 操作 | 可观察的结果 |
| --- | --- |
| 创建项目 | 建立内部办公空间，主管承接默认岗位；创建后进入项目，不创建远端仓库 |
| 提出计划草案 | 填目标、版本、任务和可选分支关联；发送/接收确认后登记计划、任务和关联 |
| 计划分支关联 | 计划卡片可新增/查看/解除仓库和分支关联；命名、来源、父分支和合并方式不受限制 |
| 任务分支关联 | 任务拥有独立关联，可多仓、多分支，也可与其他对象引用同一分支；刷新保留 |
| Bug修复分支关联 | Bug卡片单独登记修复分支，不把计划/任务关联自动当作问题的修复分支 |
| AI进度 | 展示关联分支、演示提交引用、依据和时间；模拟观察输入自动更新估算，不改变人工状态 |
| 开发完成 | 责任人点击开发完成，明确选择实际修复范围，任务进入待测试；有其他未修问题则继续修复 |
| 测试结果 | 测试通过后已交测试且问题已解决的任务最终完成；失败直接回修复，计划随任务聚合 |
| 正式Bug | 授权测试身份直接提交并关联多个任务，立即建问题并联动任务，不另发审批票 |
| 问题协调 | 查看和更新协调机器人；各任务修复/复测结果分开，协调不替其他人验收 |
| 普通工作材料 | 界面/本地AI/CLI来源按本人入账，自动生成带时间和机器人归属的报告文件；分析为只读说明 |
| 发布/部署回报 | 成功、失败、进行中均保存；流程未齐也不拒收现实声明，不以接收报告冒充成功 |
| 项目资料 | 按项目/计划筛选目录，查看报告及原文；上传1MB内文本、Markdown、JSON、CSV、PNG、JPEG |
| 岗位交接 | 主管兜底、替换任职者；资料和业务责任仍归机器人，原作者和私人偏好不改写 |

建议用经理体验计划及关联，用开发体验任务进度和明确完成，用测试体验直接Bug/复测，用运维体验发布回报。示例含同岗两个独立开发机器人。

## 自由分支的准确边界

- 支持自定义、中文及任意业务命名，不要求feature/release/bugfix前缀。
- 不要求从main、计划分支或指定release切出，不校验祖先关系或Git来源资格。
- 同一分支可关联多个对象，同一对象可关联多个仓库分支。
- 校验仅涉及项目/对象权限、仓库和分支非空、同对象重复关联等平台信息完整性。
- 解除的是平台关联，不删除、改名、合并或推送任何分支。
- 单次报告中的分支/提交引用与持久分支关联分别记录，前者描述本次上报，后者用于对象长期关联。

## AI与事件状态

普通工作说明不再要求手填百分比或走正式报告审批。关联分支的管理弹窗中，有显式标识的演示观察输入：部分实现、实现就绪、发现疑点、读取失败。它们模拟只读观察到达后的自动分析，绝不声称调用了真实Git或模型。

估算达到100%不会替开发完成。发现疑点或读取失败保留人工完成/验收，旧分析可标待更新。开发结果报告也只是材料；开发完成必须由当前责任人明确触发。测试正式结果/Bug是权限约束的业务事件，按规则直接联动。

正式计划仍有发送和接收确认、人票去重、改版、拒绝、结束只读与超时机制。审批只产生内部对象和关联，没有外部执行效果。

## 数据与未接入范围

- 新版使用judex.office.v2；旧judex.office.v1、judex.demo.v1和judex.full-concepts.v1均保留，不自动清除。
- 语言使用argus.locale，配色使用judex.office.theme；当前支持桌面中英文、深浅主题。
- 文件目录是浏览器逻辑视图，上传数据存于浏览器；空间不足时本次变更失败并提示，不当作成功。
- 本地AI/CLI只是来源模拟，尚无真实登录、CLI/API服务、Git连接或模型调用。
- SQLite会话历史、OpenSandbox执行、后端文件存储和真正的代码进度判断尚未接入。
- PDF/Office文档/多文件网页包解析、全部取消/延期/维护批次管理、完整模型与预算设置等尚未覆盖。
- 自定义岗位/机器人新增配置与真实个人AI工作会话未完整接入；示例包含同岗独立机器人，支持现有任职的接任与主管兜底。
- 演示按角色检查动作，但客户端存储不是生产认证或隐私隔离；正式工作会话权限仍需服务端落实。

## 工程结构

- types.ts、engine.ts：平台台账、正式审批与直接上报事件。
- workspace.ts：关联、模拟只读观察、明确任务动作、资料归属与权限规则。
- BranchAssociations.tsx / BranchDraftEditor.tsx：三类关联和计划草案入口。
- OfficeWork.tsx：计划、任务、Bug卡片与协调责任。
- OfficeMaterials.tsx：目录、文件上传和只读预览。
- OfficeApp / Forms / Reports / Panels：客厅、上报、正式计划确认、发布和岗位视图。
- 文案集中在src/i18n/office.ts，样式使用src/styles/office.css及共享token。
- 两个HTML入口共用office/bootstrap.tsx。
