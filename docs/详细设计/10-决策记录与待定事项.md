# 10 决策记录与待定事项

## 1. 技术轮答复追踪

编号延续当前 V2 讨论，早期 V1 的同编号问题不得混用。

| 问题 | 用户决定 | 设计落点 |
| --- | --- | --- |
| Q056 | 统一 UI 来源，Demo 只验证交互，不强制其视觉 | 前端架构；不照搬工作室皮肤 |
| Q057 | 后端 Go，HTTP 使用 Gin | 后端架构；不再以 Rust 或 chi 为并列首选 |
| Q058 | 参考 pi 四工具、上下文压缩和拼接；其他业务 Agent 工具单独实现 | Agent 设计；Go harness 为实现方案，不直接嵌入 TS pi 包 |
| Q059 | SQLite 仅作本地缓存 / 执行临时用途，文件用对象存储 | 数据设计；平台持久数据统一 PostgreSQL |
| Q060 | 公司内部使用，K8s 整套部署，Helm 开发 / 生产配置；生产可选择内置 PG 与对象存储 | 部署设计；支持两项独立选择 |
| Q061 | 确认 HeroUI | 唯一基础 UI 库 |
| Q062 | 确认 SeaweedFS | 内置 S3 存储方案 |
| 最新 Q063 | 首期即注册制；公司人员自由注册、自由创建项目；所有人平级，角色只在项目中确定 | 身份与权限；没有平台业务职级或默认超级审批人 |
| Q064 | 接受 Zustand / TanStack Query 分工 | 本地交互与服务端状态分别管理 |
| Q065 | 已有任务优先使用已分配身份；探索讨论可选择一个或多个获准身份，不自动分配正式工作 | 参与者选择与职责边界 |
| Q066 | 部署统一提供模型与凭据；项目在允许范围为职位选模型，默认继承项目设置 | 模型目录与配置继承；密钥不暴露给成员 |
| Q067 | 结果逐个返回，先处理已返回结果及独立分析；必要参与者未返回不能宣称核对完成 | 异步结果、同一主会话串行续接 |
| Q068 | 首期保持中心协调，不开放岗位自由互聊；受控讨论小组留作后续验证 | 首期协作拓扑已确定 |
| Q069 | 暂无必须接入的外部 Agent 服务 | 首期内部不强制 A2A，保留未来适配边界 |
| Q070 | 认可 SQLite 承载结构化执行上下文，平台事实仍在 PostgreSQL | 不再按轮生成大量上下文小文件；独立执行缓存 |
| Q071 | 提出项目 / 计划共享桶只读挂载、修改派生工作区 | 共享范围由 Q073、Q074 最终确定，不沿用逐文件授权方案 |
| Q072 | 允许按分析需要调用沙箱浏览器检查 HTML | 源码、视觉与交互检查分别记录 |
| Q072 后补充 | OpenSandbox 使用容器沙箱，与当前服务在同一 K8s 集群部署 | 不推导为同一个 Pod，也不推导开发生产必须同集群 |
| Q073 | 项目为共享单位，计划文件按计划 / 文件名称组织 | 计划不是独立共享授权边界 |
| Q074 | 项目内取消逐文件授权，保留项目隔离；私人提示词、密钥、私有执行上下文不进入共享区 | 覆盖此前逐材料授权的设计方案，不取消业务决定权限 |
| Q075 | 明确输出或主动提交后登记新的共享草稿；临时工作区不实时公开，原件不覆盖 | 可读、发布草稿与正式采纳分别处理 |

Q063 的提问涉及可用性，但用户回复明确的是注册和角色制度。因此**没有确认“生产允许短时不可用、内置单实例、备份恢复目标”**。不得将上一轮推荐答案记为同意。

项目邀请与注册制分别作用于不同层面；最新回复没有授权自动加入所有项目，也没有取消现有项目管理与业务验收职责。

## 2. 已确认之外的工程方案

以下保留为设计方案 / 待验证依赖，不以用户接受一项技术栈推定全部批准：

| 方案 | 当前状态 |
| --- | --- |
| TypeScript + Vite SPA、React Router | 建议工程基础，具体版本待锁定 |
| React Flow + ELK | 专业画布候选，需验证图规模、布局、键盘与许可证范围 |
| pgx + sqlc、迁移工具 | 建议数据访问方式，未确定具体版本 / 迁移产品 |
| PostgreSQL 持久队列 / River | 建议减少首期中间件，库选择与能力边界待验证 |
| REST + OpenAPI + SSE | 本文契约方案，未生成正式规范与客户端 |
| Go Server + Go Agent Runner | 为 Go 单体和 OpenSandbox 要求提出的执行分工 |
| 沙箱等待时释放、按运行重建 | 资源生命周期方案，需验证恢复能力与启动开销 |
| pgvector、Hindsight、Mem0 | 记忆检索候选，不作为已确认必装依赖 |
| 视觉 Token、动画密度、页面细节 | 基于 HeroUI 的设计方案，Demo 不锁定这些参数 |

## 3. 待定事项

| ID | 尚待决定 | 影响与处理原则 |
| --- | --- | --- |
| D01 | 注册凭据、企业邮箱验证 / 身份源、登录与找回方式 | 不新增注册审批，但正式实现前必须明确账号归属验证 |
| D02 | 非成员能否看到项目名称目录，以及成员发现方式 | 自由创建不等于全项目公开；未授权正文不公开 |
| D03 | 离职停用、失联恢复、最后一位项目负责人和项目转移 | 不暗中增加全局业务超级管理员；恢复能力需显式设计 |
| D04 | 生产可用性、允许停机、RPO / RTO、备份目的地 | 最新 Q063 未作答；不锁定单实例或 HA 拓扑 |
| D05 | 首批模型供应商、公司网关、费用归属与配额数值 | Q066 已确定部署统一提供可用模型和凭据，项目 / 职位只在允许范围选择；不再将这一配置责任列为未定 |
| D06 | 集群规模、并发 Agent、存储量、保留期、开发生产是否同集群 | 决定资源配置与数据服务拓扑；暂不承诺容量 |
| D07 | 数据库驱动 / 迁移 / 队列库版本及 HA 组件 | 提供候选，锁版本后验证；不引入未确认的常驻中间件 |
| D08 | 私有数据与项目共享区的技术隔离、退出项目后的访问撤销 | 项目共享业务文件不设逐文件授权已由 Q074 确定；项目目录公开程度仍见 D02 |
| D09 | 容器沙箱粒度、镜像、网络限制、恢复与预热复用策略 | 容器形态及与业务服务同 K8s 已确认；具体实现必须通过隔离与异常测试 |
| D10 | CLI 本人明确同意的交互凭证、认证授权与撤销 | 不能信任模型填写 human_confirmed；保持无需 Web 重复确认的已定体验 |
| D11 | 多人审批的字段与边界：代批首次计时、撤回、并发临界处理 | 已确认的全体满足、退回取消与超时规则不可改变；边角需明确 |
| D12 | Bug 类型、环境发布上报、多分支引用与复杂依赖编辑 | 通用对象可容纳，不自动继承 V1 Git / 发布强约束 |
| D13 | 记忆后端及中文材料评测目标 | 先验证再确定额外服务，不将向量索引等同于业务记忆 |
| D14 | Helm 子 Chart 固定版本、已有 CRD 归属、入口 / TLS / StorageClass 前提 | 安装前明确并加入检查，保证整套安装而不争抢现有资源 |
| D15 | 内置 SeaweedFS / 外部 S3 的只读挂载适配、Bucket / 前缀映射、缓存一致性与性能 | 项目共享单位已确认，具体驱动和参数仍需 PoC，不能承诺直接挂载任意 S3 即可 |

这些待定项不阻止已确认内容入文档，也不表示需要重新讨论全部产品规则。影响实现的项在对应模块开发前解决，其他可继续迭代。

## 4. 官方参考

以下资料用于解释框架能力和设计参考，不表示已安装或已经锁定生产版本。讨论时已核对对应官方说明；实施前重新核对版本与兼容性。

- [Gin 官方文档](https://gin-gonic.com/en/docs/)：Go HTTP 层。
- [pgx](https://github.com/jackc/pgx)、[sqlc](https://github.com/sqlc-dev/sqlc)、[River](https://riverqueue.com/docs)：数据与持久任务工程候选。
- [PostgreSQL 锁定与队列式读取](https://www.postgresql.org/docs/current/sql-select.html)、[SQLite WAL](https://www.sqlite.org/wal.html)：事务、并发与 SQLite 的使用边界。
- [pi Agent Core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)、[上下文压缩](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)：参考其机制，不直接采纳全部编码 Agent 默认行为。
